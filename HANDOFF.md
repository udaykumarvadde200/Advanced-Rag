## Open issues / known gaps
- Correctness = keyword match (strict; q035 miss is partly the metric). Groundedness = token-overlap proxy (counts citation text as ungrounded). Both are crude until S4/S5.
- The synthetic corpus is small and easy; chunking cannot be stressed on it and retrieval is near ceiling (S1 confirmed). State this in the final report; S7 may change the corpus.
- Paraphrase advantage of dense/hybrid is unproven (n=8). Paired bootstrap CI is degenerate for 1-3 discordant questions: rely on won/lost + sign test.
- OllamaReranker costs one LLM call per candidate chunk (slow); off by default.
- Stand-in server and MockLLM prove plumbing only.
- Safety checks are keyword/canary based: paraphrased or digit-by-digit PII leaks are not detected (S4 judge); jailbreak pass is strict and flags harmless non-refusals as failures; n per category is 16 to 25.
- Real S2 findings to carry into S5/S6: (a) the 3B model obeyed one inline injection (1/17); a mitigation (e.g. spotlighting/delimiting context, stripping imperative lines) would be an S6 ablation, run on the same 17 cases; (b) 3 exposed injection cases answered "I don't know": to attribute, add a clean control (same question, injection removed) and compare; (c) n06-style near-miss hallucination ("twice a year" -> 2) is a generation failure for S5.
- `MockLLM(naive=True)` obeys only three injection markers, so the proof shows the detectors fire, not how real models behave.
- Windows: `core.autocrlf=true`, so LF/CRLF warnings on `git add` are harmless. Venv must be active and `ollama serve` running before eval/sweep.

- S3 gate: latency gate only meaningful on the same hardware; safety case results (e.g. injection i08) can differ between sessions, and the zero-tolerance new-failing-case rule will flag a flip back, so read the answer before calling it a regression; the baseline is tied to the S1/S2 metrics (keyword correctness etc.) and must be re-frozen after S4.
- `cli.py regress --compare` runs the golden set + the whole safety suite (about 200 LLM calls + 1230 retrievals): minutes, not seconds, on the user's machine.

- S4: judge validated only for correctness, roughly (kappa 0.55, wide CI, noisy across seeds, not better than keywords); faithfulness/relevancy unvalidated (no hallucinated labels); labels partly made with Claude's guidance; n=30, one labeler, error-enriched sample. Judge cost is high: several LLM calls per answer on a 7B model partly offloaded on 6 GB VRAM; `--probe` first. DeepEval's API changes between versions (the version is recorded in each result file). `injection_obedience` unvalidated. The regression gate still uses keyword metrics; re-freeze as v2 only after validation.
- S5: reference 61/69 vs baseline 59/69: `gen` sent different requests than `eval` (warm-up context; retrieved run after the gold run); fixed in code, effect unverified until the re-run. LESSON: the grid was run twice (same old code, Ollama restarted between): reference 61/69 both times but k2/reverse/doc moved by +-1 question and one failure was reclassified, so answers repeat only to about +-1 question across sessions; also compare runs with the same call history. Per-type attribution and the 2 metric artifacts not inspected yet. Prompt variants were designed after seeing q033/q035 on the same golden set (biased; fresh questions needed, S7).
